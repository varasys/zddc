1. Overview

ZDDC — Zero Day Document Control — is one naming convention plus a flat folder structure. It makes no hierarchy decisions for you.

Every filename carries project, discipline, type, sequence, revision, status, and title. Your file browser is the search engine.

The four tools implement interfaces around this structure — but they're optional. The structure works without them.

2. Filename format

Grammar:

trackingNumber_revision (status) - title.extension

Rules:

  • Tracking number: no spaces, no underscores, hyphens as separators
  • Underscore _ separates tracking number from revision
  • Revision: no spaces; may include ~ prefix and/or + modifier
  • Space before (status)
  • Space-dash-space - before title
  • Extension is the original file extension, preserved exactly

Anatomy:

123456-EL-SPC-2623 _ B (IFC) - Specification For Switchgear.pdf

Real examples:

123456-EM-MDL-0001_A (IFR) - Master Deliverables List.pdf 123456-EL-SPC-2623_A (IFR) - Specification For Switchgear.pdf 123456-EL-ARR-0003_A+C1 (RSB) - Electrical Room Equipment Arrangement.pdf 123456-EL-ARR-0003_0 (IFC) - Electrical Room Equipment Arrangement.pdf 123456-ME-RFI-0024_A (IFR) - Mechanical Room Size RFI.pdf

3. Tracking numbers

A tracking number is the document's permanent identifier. It never changes — regardless of revision, status, or content changes. Think of it like a passport number — your name can change, but your passport number does not.

Format is your choice. Must be consistent within a project. No spaces, no underscores — hyphens as separators only.

Common pattern: PROJECT-DISCIPLINE-TYPE-SEQUENCE

Example schemas

Project type Example Schema
Engineering 123456-EL-SPC-2623 project · discipline · type · sequence
Construction PROJ-STR-DWG-0001 project · discipline · type · sequence
Legal SMITH-2025-CTR-0014 client · year · type · sequence
Research RNA-SEQ-EXP-0042 program · method · type · sequence
Small project MCH-2025-001 client · year · sequence

Benefits of encoded discipline and type: Search EL to find all electrical documents. Search SPC to find all specifications. Sort by name and the entire project groups together.

4. Revisions

Letters A, B, C... for design/review phase. Numbers 0, 1, 2... for construction/record phase (post-approval). Letters sort before numbers — this is intentional (lexical sort is meaningful).

Revision Meaning
A First issued revision
B Second issued revision
C, D, … Subsequent revisions
0 First numeric revision (typically after approval, IFC)
1, 2, … Subsequent numeric revisions

5. Draft prefix (~)

~ before revision = working draft, not yet formally issued. Keeps working files alongside formal versions without ambiguity.

  • ~A = draft that will become Rev A when issued
  • ~B = working version incorporating Rev A comments

~ sorts after the base revision, so drafts are clearly subordinate.

123456-EL-SPC-2623_~A (---) - Working draft of Rev A — not yet issued 123456-EL-SPC-2623_A (IFR) - Rev A — formally issued for review

6. Revision modifiers (+)

+modifier associates a file with a base revision without incrementing it. Used for comments, backup material, quality records, and internal notes. Sorts after the base revision in alphabetical order.

Modifier Meaning Typical status
+C1, +C2 Comments on the base revision RSA RSB RSC RSD
+B1, +B2 Backup material supporting base content IFI
+N1, +N2 Internal notes (not for general distribution) IFI
+Q1, +Q2 Quality check records RSA RSI

7. Status codes

Primary status codes

Used on formally issued deliverables:

Code Meaning What's expected
DFT Draft Internal working version — not for external distribution
IFA Issued For Approval Formal sign-off required before proceeding
IFB Issued For Bid Price to this — binding scope
IFC Issued For Construction Build to this — approved
IFD Issued For Design Reference for downstream design work
IFI Issued For Information No action required — for awareness only
IFP Issued For Purchase Procurement may proceed to this version
IFR Issued For Review Please review and return comments
IFU Issued For Use Approved for operational use
REC Issued For Record Final as-built or archived version
--- Status unknown Working version — status not yet determined

Review status codes

Used with revision modifiers like +C1:

Code Meaning What it means
RSA Review Status A No comments — approved as submitted
RSB Review Status B Incorporate comments, resubmit for record
RSC Review Status C Incorporate comments, resubmit before proceeding
RSD Review Status D Rejected — resubmit per stated requirements
RSI No Review Required Supplemental information only

8. Folder naming

Transmittal folders follow the same convention, date-prefixed so folders sort chronologically:

Format: YYYY-MM-DD_trackingNumber (status) - title

2025-10-31_123456-EM-SUB-0001 (IFR) - General Arrangement for Review 2025-10-31_123456-EL-TRN-0043 (IFC) - Electrical Design Issued For Construction 2025-11-12_123456-ME-RFI-0024 (IFR) - Mechanical Room Size RFI (question) 2025-11-19_123456-ME-RFI-0024 (IFU) - Mechanical Room Size RFI (response)

9. Transmittal workflow

The directory structure:

project/ incoming/ ← sender deposits transmittal folders here received/ ← permanent record of accepted transmittals issued/ ← your copies of transmittals you sent

5-step workflow:

  1. 1

    Sender creates transmittal folder

    Sender creates a correctly named transmittal folder and uploads to receiver's incoming/

  2. 2

    Receiver validates

    Receiver checks filenames, completeness, and SHA-256 checksums

  3. 3

    Receiver accepts

    Receiver moves folder from incoming/ to received/ — it is now a permanent record

  4. 4

    Receiver records hashes

    Receiver saves an acknowledgment with SHA-256 hashes — establishes the "official" version

  5. 5

    Receiver notifies

    Receiver notifies sender and distribution list, including SHA-256 hashes

What SHA-256 gives you: Mathematical fingerprint of file contents. Single byte change → hash changes. When acknowledgment records hashes, you can verify years later that the file is identical to what was transmitted.

When shared directories aren't available

Use rsync or rclone to replicate the received/ folder between sites. Cloud storage (SharePoint, Google Drive, Dropbox) also works — the workflow is filesystem-agnostic.

10. Tools

Four single-file HTML applications — each is complete and self-contained. Save them locally and they work forever, without internet, without updates, without a subscription.

Archive Browser
Browse, search, filter your project folder. Filter by tracking number, discipline, revision, status, or free text. Group by transmittal. Download selected files as ZIP.
Open Archive Browser
Transmittal Creator
Fill in metadata, drag in files, publish a self-contained HTML transmittal record with SHA-256 checksums. Supports digital signatures. The published file IS the transmittal record.
Create Transmittal
Document Classifier
Spreadsheet-like interface for bulk-renaming files to ZDDC format. Copy/paste with Excel. Point it at a folder, fill in the columns, save all at once.
Run Classifier
Markdown Editor
Browser-based markdown editor with live preview, YAML front matter support, and table of contents. Direct local file access via File System Access API.
Open Editor

All tools require Chrome or Edge (File System Access API).
